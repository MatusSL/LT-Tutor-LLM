SUPABASE DATABASE + AUTH ROADMAP FOR LT-TUTOR-LLM
===================================================
Single user, but implementing auth and RLS properly as a learning exercise.


PHASE 1: PROJECT SETUP
-----------------------
1. Install Supabase CLI: brew install supabase/tap/supabase
2. Initialize: supabase init (creates supabase/ directory with config.toml)
3. Start local Supabase: supabase start
   - This gives you a local Postgres, Auth, Storage, and Dashboard
   - Dashboard at http://localhost:54323
   - Note the anon key, service role key, and API URL from the output
4. Create your first migration: supabase migration new initial_schema


PHASE 2: SCHEMA (SQL MIGRATION)
--------------------------------
Create these tables in order (respecting foreign key dependencies):

Table 1: profiles
  - id uuid PK -> auth.users(id) ON DELETE CASCADE
  - display_name text
  - target_language text NOT NULL DEFAULT 'spanish'
  - created_at timestamptz DEFAULT now()
  - updated_at timestamptz DEFAULT now()
  - Add trigger: auto-create profile row when a user signs up
  - Add trigger: auto-update updated_at on row change

Table 2: episodes (static catalog)
  - id serial PK
  - language text NOT NULL (check constraint for valid languages)
  - episode_number integer NOT NULL
  - episode_type text NOT NULL (check: orientation/structure/vocabulary)
  - unlocked_tenses text[] DEFAULT '{}'
  - UNIQUE(language, episode_number)

Table 3: words (canonical dictionary)
  - id uuid PK DEFAULT gen_random_uuid()
  - language text NOT NULL
  - word text NOT NULL
  - translation text (English meaning, for flashcards)
  - is_high_frequency boolean DEFAULT false
  - source_episode_id integer -> episodes(id)
  - UNIQUE(language, word)

Table 4: user_episode_progress
  - id uuid PK DEFAULT gen_random_uuid()
  - user_id uuid NOT NULL -> auth.users(id) ON DELETE CASCADE
  - episode_id integer NOT NULL -> episodes(id)
  - completed_at timestamptz DEFAULT now()
  - UNIQUE(user_id, episode_id)

Table 5: user_vocabulary
  - id uuid PK DEFAULT gen_random_uuid()
  - user_id uuid NOT NULL -> auth.users(id) ON DELETE CASCADE
  - word_id uuid NOT NULL -> words(id) ON DELETE CASCADE
  - times_used integer DEFAULT 1
  - mistakes integer DEFAULT 0
  - last_used_at timestamptz DEFAULT now()
  - unlocked_at timestamptz DEFAULT now()
  - UNIQUE(user_id, word_id)

Table 6: chat_sessions
  - id uuid PK DEFAULT gen_random_uuid()
  - user_id uuid NOT NULL -> auth.users(id) ON DELETE CASCADE
  - language text NOT NULL DEFAULT 'spanish'
  - started_at timestamptz DEFAULT now()
  - ended_at timestamptz
  - is_active boolean DEFAULT true

Table 7: chat_messages
  - id uuid PK DEFAULT gen_random_uuid()
  - session_id uuid NOT NULL -> chat_sessions(id) ON DELETE CASCADE
  - user_id uuid NOT NULL -> auth.users(id) ON DELETE CASCADE
  - role text NOT NULL (check: user/tutor)
  - content text NOT NULL
  - tutor_response jsonb (full TutorResponse for tutor messages, null for user)
  - audio_url text
  - created_at timestamptz DEFAULT now()

Table 8: review_items
  - id uuid PK DEFAULT gen_random_uuid()
  - language text NOT NULL
  - type text NOT NULL (check: flashcard/phrase_quiz/fill_blank/error_correction)
  - difficulty text DEFAULT 'easy' (check: easy/medium/hard)
  - content jsonb NOT NULL (shape depends on type, see below)
  - source_episode_id integer -> episodes(id)
  - word_id uuid -> words(id)
  - created_at timestamptz DEFAULT now()

  JSONB content shapes by type:
    flashcard:         { "spanish": "...", "english": "..." }
    phrase_quiz:       { "phrase": "...", "correct_answer": "...", "options": [...] }
    fill_blank:        { "sentence": "...", "correct_word": "...", "options": [...], "translation": "..." }
    error_correction:  { "words": [...], "error_index": N, "corrected_word": "...", "error_type": "...", "explanation": "..." }

Table 9: user_review_attempts
  - id uuid PK DEFAULT gen_random_uuid()
  - user_id uuid NOT NULL -> auth.users(id) ON DELETE CASCADE
  - review_item_id uuid NOT NULL -> review_items(id) ON DELETE CASCADE
  - was_correct boolean NOT NULL
  - attempted_at timestamptz DEFAULT now()


PHASE 3: INDEXES
-----------------
Add these after table creation:
  - episodes(language)
  - words(language)
  - words(source_episode_id)
  - user_episode_progress(user_id)
  - user_vocabulary(user_id)
  - user_vocabulary(user_id, last_used_at DESC)
  - user_vocabulary(user_id, mistakes DESC)
  - chat_sessions(user_id, is_active) WHERE is_active = true
  - chat_sessions(user_id, started_at DESC)
  - chat_messages(session_id, created_at)
  - chat_messages(user_id, created_at DESC)
  - chat_messages USING GIN (tutor_response jsonb_path_ops) WHERE tutor_response IS NOT NULL
  - review_items(language, type)
  - review_items(language, type, difficulty)
  - user_review_attempts(user_id, attempted_at DESC)
  - user_review_attempts(user_id, review_item_id)


PHASE 4: RLS (ROW LEVEL SECURITY)
-----------------------------------
This is the key learning part. RLS makes Postgres enforce data isolation.

Step 1: Enable RLS on every table
  ALTER TABLE public.<table_name> ENABLE ROW LEVEL SECURITY;

Step 2: Add policies

  profiles:
    SELECT -> auth.uid() = id
    UPDATE -> auth.uid() = id
    (user can only see/edit their own profile)

  episodes, words, review_items (shared catalogs):
    SELECT -> auth.role() = 'authenticated'
    (any logged-in user can read, nobody can write from client)

  user_episode_progress, user_vocabulary, chat_sessions, chat_messages, user_review_attempts:
    ALL -> auth.uid() = user_id (USING and WITH CHECK)
    (user can only CRUD their own rows)

Step 3: Test RLS
  - In Supabase Dashboard > SQL Editor, run queries as anon vs authenticated
  - Use supabase.auth.signUp() to create your user
  - Query with the client library and verify you only see your data
  - Try inserting a row with a different user_id — should be denied


PHASE 5: AUTH SETUP (FRONTEND)
-------------------------------
1. Install: npm install @supabase/supabase-js in frontend/my-app/
2. Create a Supabase client:
     import { createClient } from '@supabase/supabase-js'
     const supabase = createClient(SUPABASE_URL, SUPABASE_ANON_KEY)
3. Sign up your single user:
     const { data, error } = await supabase.auth.signUp({
       email: 'you@example.com',
       password: 'your-password'
     })
4. Sign in:
     const { data, error } = await supabase.auth.signInWithPassword({
       email: 'you@example.com',
       password: 'your-password'
     })
5. Get session token for backend calls:
     const { data: { session } } = await supabase.auth.getSession()
     // Pass session.access_token in Authorization header to your FastAPI backend
6. Listen for auth state changes (auto-refresh tokens):
     supabase.auth.onAuthStateChange((event, session) => { ... })


PHASE 6: AUTH VALIDATION (BACKEND)
------------------------------------
1. Install: uv add supabase (or PyJWT + httpx for manual validation)
2. In FastAPI, create a dependency that extracts user_id from the JWT:
     - Read Authorization header
     - Verify JWT signature using your Supabase JWT secret
     - Extract user_id from the 'sub' claim
3. Use user_id in all database queries
4. For Supabase client queries from backend, pass the user's JWT:
     supabase.postgrest.auth(token) — this makes RLS work server-side too


PHASE 7: SEED DATA
--------------------
1. Write a Python script that reads all Track_{n}.json files
   and inserts rows into episodes and words tables
2. For words.translation, either:
   - Add translations manually for the words you care about
   - Batch-generate via LLM (send word + context, get English translation)
3. Seed review_items from the mock data currently in the frontend
   (see frontend/my-app/app/(tabs)/review.tsx and the review sub-screens)
4. Run: supabase db reset (applies migrations + seed)


PHASE 8: WIRE IT UP
---------------------
1. Replace backend/src/app/database/firestore.py with a Supabase client
2. Rewrite backend/src/app/services/vocabulary.py to use Supabase/Postgres
3. Add chat persistence in tutor_core.py (save messages to chat_messages)
4. Add endpoints or modify existing ones to support:
   - GET /chat/history — fetch past chat sessions
   - GET /review/items?type=flashcard — fetch review content
   - POST /review/attempts — log review results
5. Update frontend API calls to pass Authorization header
6. Replace mock data in review screens with real API calls
