Day 1 — Understand the Problem (no code)
                                                                                                                                                                    
  Before writing a single line, you need to understand what auth actually is and why it's two separate things.
                                                                                                                                                                    
  Concepts to learn:                                                                                                                                              
                                                                                                                                                                    
  Authentication vs Authorization — two words people conflate constantly:                                                                                           
  - Authentication (AuthN): "Who are you?" — proving identity. Logging in.
  - Authorization (AuthZ): "What are you allowed to do?" — permissions. Can user A see user B's vocabulary?                                                         
                                                                                                                                                                  
  Your current API key is neither. It doesn't identify anyone, and it doesn't restrict anything per-user. It's just a gate.                                         
                                                                                                                                                                    
  The three classic factors:                                                                                                                                        
  1. Something you know (password)                                                                                                                                  
  2. Something you have (phone, hardware key)                                                                                                                       
  3. Something you are (fingerprint)         
                                                                                                                                                                    
  Your app will use factor 1 (password). That's fine for now. Know that production apps layer on factor 2 (2FA) later.                                              
                                                                                                                                                                    
  Why passwords can't be stored as-is:                                                                                                                              
  - If your database leaks, every user's password is exposed                                                                                                        
  - Users reuse passwords across sites — one breach cascades                                                                                                        
  - Solution: hashing — a one-way function. You store the hash, not the password. When the user logs in, you hash what they typed and compare hashes.             
  - But plain hashing isn't enough — rainbow tables (precomputed hash lookups) defeat it                                                                            
  - Solution: salting — prepend a random string before hashing. Each user gets a unique salt. Now rainbow tables are useless.                                       
  - bcrypt does both (hashing + salting) automatically. That's what you'll use.                                                                                     
                                                                                                                                                                    
  Sessions vs Tokens:                                                                                                                                               
  - Session-based: Server stores a session object, gives client a session ID cookie. Server is stateful — it has to remember every active session.                  
  - Token-based (JWT): Server creates a signed token containing {user_id, exp}, gives it to the client. Client sends it on every request. Server just verifies the  
  signature — no state needed. This is what you'll use.                                                                                                           
                                                                                                                                                                    
  Homework for Day 1:                                                                                                                                             
                                                                                                                                                                    
  1. Read what a JWT looks like: go to jwt.io and paste an example token. Notice the three parts: header, payload, signature. Understand that the payload is not    
  encrypted — anyone can decode it. The signature only proves it wasn't tampered with.                                                                              
  2. Answer these questions for yourself:                                                                                                                           
    - Why can't you just send user_id: 5 in the request body instead of using JWT?                                                                                  
    - What happens if someone steals a JWT? How is that different from stealing a password?                                                                         
    - Why does a JWT have an expiration time?                                                                                                                       
    - In your current code, what stops user A from reading user B's vocabulary? (Answer: nothing — there's only one user.)
