Day 2 — Design the Data Model (schema only, no endpoints)                                                                                                         
                                                                                                                                                                    
  What changes in the database:
                                                                                                                                                                    
  Your current users table has display_name, max_episode, language. It needs:                                                                                       
                                                                                                                                                                    
  users                                                                                                                                                             
    id            (uuid, PK — already exists)                                                                                                                     
    email         (text, unique, NOT NULL)  ← new                                                                                                                   
    password_hash (text, NOT NULL)          ← new                                                                                                                   
    display_name  (text)                                                                                                                                            
    max_episode   (int)                                                                                                                                             
    language      (text)                                                                                                                                          
    created_at    (timestamp)                                                                                                                                       
                                                                                                                                                                  
  Your words and mistakes tables currently have no user_id. Every word belongs to everyone (in practice, just you). They need:                                      
  
  words                                                                                                                                                             
    id, word, translation, ...                                                                                                                                    
    user_id  (uuid, FK → users.id)  ← new

  mistakes
    id, origin, corrected, ...
    user_id  (uuid, FK → users.id)  ← new                                                                                                                           
  
  Task for Day 2:                                                                                                                                                   
                                                                                                                                                                  
  1. Write the SQL migration that adds email and password_hash to users, and user_id FK to words and mistakes                                                       
  2. Write a backfill query: set all existing rows' user_id to your current user's ID
  3. After backfill, make user_id NOT NULL                                                                                                                          
  4. Think about: what happens if you make user_id NOT NULL before backfilling? (Answer: the migration fails because existing rows have NULL.)                    
                                                                                                                                                                    
  Key concept — Row-Level Security (RLS):                                                                                                                         
                                                                                                                                                                    
  Even after adding user_id, nothing prevents a query like SELECT * FROM words from returning everyone's words. The application code might filter by user_id, but if
   there's a bug, or someone hits the database directly, data leaks.
                                                                                                                                                                    
  RLS is a Postgres feature where the database itself enforces "you can only see your own rows." The policy says: USING (user_id = auth.uid()). Even if your code   
  forgets to filter, Postgres won't return other users' data.                                                                                                     
                                                                                                                                                                    
  You'll set this up in Supabase's SQL editor.
