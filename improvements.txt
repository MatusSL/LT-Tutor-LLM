LT-Tutor-LLM — Improvement Suggestions
Last audited: 2026-04-10

Context
Full codebase audit of both backend and frontend to identify the highest-impact improvements for this bilingual Spanish tutor app.

================================================================================

Priority 1: Security (Fix Now)

1a. Firebase key still committed to git
- backend/lt-tutor-firebase-key.json is tracked in git (confirmed via `git ls-files`)
- The database has been migrated to Supabase (backend/src/app/database/supabase_setup.py), so
  this key is now dead/unused — but it is still a credential leak
- Fix: `git rm --cached backend/lt-tutor-firebase-key.json`, add to .gitignore, rotate the key

1b. CORS wildcard
- backend/main.py uses allow_origins=["*"]
- Fix: Restrict to your actual frontend origins

1c. Hardcoded single user
- DB operations in backend/src/app/services/vocabulary.py hardcoded to display_name="matus"
  (see vocabulary.py lines with `.eq(User.DISPLAY_NAME, "matus")`)
- Fix: Pass user identity through the request; even a simple header is enough for now

================================================================================

================================================================================

Priority 3: Robustness

3a. Backend error handling
- No global exception handler — unhandled errors return raw 500s
- Silent except Exception: pass in multiple agents makes debugging hard
- No error handling on DB operations
- Fix: Add FastAPI exception handler middleware, replace silent catches with logging

3b. Add logging
- All diagnostic output uses print() — no structured logging
- Fix: Replace with Python logging module, add request logging middleware

3c. Frontend error boundaries
- No React error boundaries — a rendering error crashes the entire app
- Fix: Add error boundary wrapper around tab navigator and review stack

3d. Health check depth
- /health returns static {"status": "ok"} without checking DB or LLM connectivity
- Fix: Add Supabase ping and LLM availability check

================================================================================

Priority 4: Architecture Improvements

4a. Frontend state management
- Review data passed as JSON-serialized route params (could hit URL length limits)
- Chat screen has 15+ useState calls; episode data fetched independently in two screens
- Fix: Add React Context or Zustand for shared state (review data, episode state, server status)

4b. Deduplicate episode selector
- EpisodeSelector component (components/chat/EpisodeSelector.tsx) and LecturesScreen
  (app/(tabs)/lectures.tsx) implement identical episode list UI and selection logic independently
- Fix: Have lectures.tsx use the existing EpisodeSelector component

4c. Deduplicate review screen structure
- All 4 review screens share the same shell (header, progress bar, score, finished state)
- Fix: Extract a ReviewShell wrapper component

4d. Singleton on import
- build_tutor_core.py creates _tutor_core_instance at import time — if any dependency fails,
  the app won't start with a useful error
- Fix: Use FastAPI's lifespan event or lazy initialization with proper error handling

================================================================================

Priority 5: Polish

5a. Accessibility
- No accessibilityLabel, accessibilityRole, or accessibilityHint on any interactive elements
- Fix: Add accessibility props to buttons, inputs, quiz options, flashcards

5b. Loading states
- Review screen has no loading indicator while fetching data
- Lectures screen has no loading state during episode fetch
- Fix: Add loading spinners/skeletons

5c. Topic type defined twice with different shapes
- services/tutor-api.ts defines Topic with 4 fields (display_name, description, suggested_goals, difficulty)
- components/chat/types.ts defines Topic with only 1 field (display_name)
- Fix: Delete the definition in types.ts, import the canonical one from tutor-api.ts

5d. Frontend tests
- Zero test files in the frontend
- Fix: Add at least component tests for chat bubbles and review logic

5e. Backend integration tests
- No route-level tests using FastAPI TestClient
- Fix: Add endpoint tests for /chat, /episode, /review
