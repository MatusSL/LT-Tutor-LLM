BACKEND REVIEW ENDPOINTS — Implementation Plan
================================================

The Review screen needs 4 backend endpoints to replace the mock data currently
hardcoded in the frontend. Each endpoint is described below with its purpose,
request/response contract, and implementation hints.


1. GET /vocabulary
─────────────────
Purpose: Return all unlocked words with their stats for Flashcards + general review.

Response:
{
  "words": [
    {
      "word": "hola",
      "english": "hello",
      "times_used": 5,
      "mistakes": 1,
      "last_used": "2026-03-27T14:30:00",
      "is_high_frequency_word": true
    }
  ],
  "total": 42,
  "episode": 30
}

Implementation:
- Add get_all_words_with_stats() to vocabulary.py
  - Query all docs from `unlocked_words` collection
  - Return full document fields (not just word strings like load_vocabulary does)
- English translations: either
  (a) Add an "english" field to each word doc in Firestore (populate during /chat
      using tutor_response.input_english / response_english), OR
  (b) Add a batch translation step using the LLM when this endpoint is called
  Option (a) is recommended — zero latency, builds up over time

Schema (models.py):
  class VocabularyWord(BaseModel):
      word: str
      english: str
      times_used: int
      mistakes: int
      last_used: datetime | None
      is_high_frequency_word: bool

  class VocabularyResponse(BaseModel):
      words: list[VocabularyWord]
      total: int
      episode: int


2. POST /review/quiz
────────────────────
Purpose: Generate phrase translation quiz questions.

Request:
{
  "count": 10   // number of questions to generate
}

Response:
{
  "questions": [
    {
      "phrase": "Me alegra verte otra vez.",
      "correct_answer": "I'm glad to see you again.",
      "options": [
        "I'm glad to see you again.",
        "I need to see you later.",
        "I'm happy to help you.",
        "It makes me sad to leave."
      ]
    }
  ]
}

Implementation:
- Use the LLM to generate quiz questions from the user's vocabulary
- Prompt the LLM with the user's unlocked words and ask it to:
  1. Create Spanish phrases using those words
  2. Provide the correct English translation
  3. Generate 3 plausible but incorrect distractors
- Alternatively, store phrases from chat history (user + tutor messages)
  in a new Firestore collection `chat_phrases` and use those as quiz material

Schema:
  class QuizQuestion(BaseModel):
      phrase: str
      correct_answer: str
      options: list[str]   # 4 items, shuffled, includes correct_answer

  class QuizResponse(BaseModel):
      questions: list[QuizQuestion]


3. POST /review/fill-blank
──────────────────────────
Purpose: Generate fill-in-the-blank exercises.

Request:
{
  "count": 10
}

Response:
{
  "questions": [
    {
      "sentence": "Me alegra ____ otra vez.",
      "correct_word": "verte",
      "options": ["verte", "comer", "salir", "tener"],
      "translation": "I'm glad to see you again."
    }
  ]
}

Implementation:
- Use the LLM to generate sentences from the user's vocabulary
- Prompt should ask for:
  1. A natural Spanish sentence using the user's known words
  2. Which word to blank out (prefer vocabulary words, not articles/prepositions)
  3. The correct word
  4. 3 distractor words from the same vocabulary set (same part of speech)
  5. English translation of the full sentence
- Alternatively, take real tutor responses from chat history, blank out a
  vocabulary word, and generate distractors

Schema:
  class FillBlankQuestion(BaseModel):
      sentence: str          # with ____ placeholder
      correct_word: str
      options: list[str]     # 4 items, shuffled
      translation: str

  class FillBlankResponse(BaseModel):
      questions: list[FillBlankQuestion]


4. POST /review/error-correction
─────────────────────────────────
Purpose: Generate sentences with deliberate errors for the user to find.

Request:
{
  "count": 10
}

Response:
{
  "questions": [
    {
      "words": ["Yo", "soy", "muy", "contenta", "hoy."],
      "error_index": 3,
      "corrected_word": "contento",
      "error_type": "agreement",
      "explanation": "With 'yo' (masculine speaker), use 'contento' not 'contenta'."
    }
  ]
}

Implementation:
- Best approach: Pull from the user's ACTUAL mistake history
  - During /chat, the tutor_response already contains error_candidates with
    word, error_type, suggested_correction, explanation
  - Store these in a new Firestore collection `user_errors`:
    {
      original_sentence: str,
      error_word: str,
      corrected_word: str,
      error_type: str,
      explanation: str,
      timestamp: datetime
    }
  - When this endpoint is called, retrieve stored errors and format them
- Fallback: Use the LLM to generate sentences with common errors based on
  the user's vocabulary and error patterns

Schema:
  class ErrorCorrectionQuestion(BaseModel):
      words: list[str]
      error_index: int
      corrected_word: str
      error_type: str
      explanation: str

  class ErrorCorrectionResponse(BaseModel):
      questions: list[ErrorCorrectionQuestion]


DATA COLLECTION (wire into existing /chat flow)
================================================

To make review content personalized, collect data during chat sessions:

1. In tutor_core.py handle_message(), after processing a response:
   - Store the tutor's Spanish phrases in a `chat_phrases` collection
     (for phrase quiz + fill-in-the-blank source material)
   - Store error_candidates in a `user_errors` collection
     (for error correction exercises)
   - Store word-level translations when available
     (for flashcard English sides)

2. In vocabulary.py, extend insert_word() to also store the English
   translation when available.


FIRESTORE COLLECTIONS SUMMARY
==============================

Existing:
  unlocked_words  — word stats (extend with "english" field)
  episodes        — max_episode_completed

New:
  chat_phrases    — {spanish, english, episode, timestamp}
  user_errors     — {original_sentence, words, error_index, corrected_word,
                      error_type, explanation, timestamp}
